环境：本机 3120×1984 @ 200%，Edge 专用实例，页面 `web/bench/page.html`（本地文件，排除网络抖动），`bench.ps1 -N 5`，单位 ms（整条 `cu.exe` 命令的墙钟时间，含管道开销 ~45ms），取中位数。

真实站点抽查（百度首页新版）：`web els` 33 个元素，正确列出可见的对话输入框(#13)与"百度一下"(#14)，`type -Id 13` + `click -Text 百度一下` + `wait -Url wd=` 全流程 ~1s，搜索词正确；对隐藏的 `#kw` 输入会返回 `visible:false` 警告。

已知边界：
- 浏览器窗口**最小化**时没有帧，真实鼠标事件会卡住 → 自动退回 DOM click（`frames:false`）。被其它窗口遮挡不再是问题（启动参数已处理，旧实例需 `web stop` 一次）。
- `-Text` 不搜索跨域 iframe（浏览器安全限制）；同源 iframe / open shadow DOM 可以。
- `-Text` 的候选排序是启发式：同名元素多时看返回的 `count`/`alts`，用 `-Index` 或 `-Id` 明确。

复测中发现并修掉的问题：
1. 点开新标签后会话仍留在旧标签 → 自动跟随新标签（`Target.getTargets` 前后对比；有 `target=_blank` 提示时多等 1.5s）。
2. 会话标签变成后台标签（`document.hidden`）→ 鼠标事件卡住、按键被站点忽略 → 输入前自动 `Target.activateTarget`，`open` 完也会把自己的标签置前（不改系统焦点）。
3. `web open` 对 load 事件迟迟不来的页面（京东、GitHub）直接超时 → DOM 就绪 1.2s 后按 `interactive` 返回。
4. `type` 的 setter 模式对必应这类维护自身输入状态的搜索框，回车不提交 → 默认改为可信 `Input.insertText`。
5. `Input.*` 事件在页面跳转/繁忙时确认迟到 → 1.5s 超时且**绝不重发**（重发 mousePressed 等于双击），返回 `ackLate:true`。
6. `wait -Url` 期间文档被销毁、页内 Promise 永不返回 → 导航类等待改用 600ms 短片。
7. `els -Sel` 找不到范围时曾退回整页误导 → 现在报 `ERR_NOT_FOUND`。
8. `-Append` 在 input/textarea 上光标位置不确定 → 追加前把光标放到末尾。
